## P1.5 — Bind worker completion to active session and view

**Evidence/gap.** `TiepDonManHinh` creates three `SwingWorker`s (refresh, save, search), tracks them in `inFlightWorkers`, and cancels them on a session change or destroy. Cancellation skips callbacks only when `isCancelled()` is true; a worker already done with a pending EDT callback can still update the panel. Completion callbacks do not check session, view lifetime, or whether the result is still the newest request. Search/save actions do not first reject an inactive lifecycle state. **Minimal implementation checklist**

- [ ] At each UI action, obtain the authorization and audit contexts from the active lifecycle service once; if either is absent or the lifecycle is not `ACTIVE`, do not start a handler call. Remove the fallback identity/scope values and random session UUID from this path. Preserve the Application authorization checks as the authority.
- [ ] Give the panel a monotonic view/session invalidation token and each refresh/search a latest-request token. Capture the tokens and session identity with the request; before any EDT mutation, dialog, or form replacement, require the panel to be undisposed, the operation still current, the captured session still current, and the lifecycle `ACTIVE`. Invalidate on lock/logout/session replacement, a superseding request, and `destroy()`. This must also reject completed-but-undelivered results; `SwingWorker.cancel()` alone is insufficient.
- [ ] Keep read completion effects view-only and discard stale results. On idle lock, keep the draft under the existing lock overlay policy; on logout, clear protected form state. Reauthentication may re-enable work only after the lifecycle again supplies valid contexts; an old worker must not be revived.
- [ ] Make save single-flight and prevent edits/New/search from changing the draft while its command is running (or equivalently guard the draft revision before applying the result). A successful old save must not clear a newer draft. Do not present UI cancellation/interruption as proof that a write rolled back; the Application transaction remains responsible for write atomicity. ## P1.6 — Keep duplicate recovery private and search behavior coherent

**Evidence/gap.** The handler maps `BenhNhanDinhDanhXungDotNgoaiLe` to generic `PATIENT_REGISTRATION_FAILED`, so the panel's special handling for `PATIENT_DUPLICATE_CCCD`/`PATIENT_IDENTITY_CONFLICT` does not match this real collision path. The ordinary failure retains the draft. Reinstating a prompt from a scope-blind database collision would disclose global CCCD existence. The current fallback search is a generic scoped substring search, not an exact CCCD match. [RegisterPatientHandler.java:129–138](../../clinic-application/src/main/java/vn/clinicmanagement/application/reception/RegisterPatientHandler.java#L129-L138) [RegisterPatientHandler.java:203–206](../../clinic-application/src/main/java/vn/clinicmanagement/application/reception/RegisterPatientHandler.java#L203-L206) [ReceptionPanel.java:499–520](../../clinic-desktop/src/main/java/vn/clinicmanagement/desktop/modules/reception/ReceptionPanel.java#L499-L520) [ReceptionPanel.java:603–612](../../clinic-desktop/src/main/java/vn/clinicmanagement/desktop/modules/reception/ReceptionPanel.java#L603-L612) [phase2-reception-write-authorization-contract.md:11–15](phase2-reception-write-authorization-contract.md#L11-L15)

Ordinary search submits phone and CCCD as separate keyword queries, unions by patient ID, shares one audit actor, treats a partial query failure as a successful partial result, and can return up to 100 distinct rows despite the handler's 50-row per-query limit. A single result immediately replaces the form; multiple results offer a cancellable chooser. Input is trimmed, but phone-search canonicalization is not defined. `SearchBenhNhanHandler` checks authorization, scopes the query, applies its 50-result limit, then audits success; a query/audit failure returns a failure result. **Minimal implementation checklist**

- [ ] Keep every global collision on the generic registration-failure path. Do not show the duplicate dialog, a masked CCCD, a special result code, or a search prompt based only on the unique-index/identity-conflict exception. Preserve the entered draft and ensure exception/log/audit detail does not contain CCCD or patient data.
- [ ] Only consider recovery when an independently authorized, explicitly scoped lookup establishes an eligible in-scope patient using the submitted CCCD exactly; the scope must be the current facility/department and satisfy the prior-visit rule. A global lookup result must never populate the form. If no such safe scoped result is available, retain the generic failure. Keep the final update subject to normal `PATIENT:SUA` and `RECEPTION:TAO` checks and the active-session check. [phase2-reception-write-authorization-contract.md:11–15](phase2-reception-write-authorization-contract.md#L11-L15)
- [ ] Snapshot the submitted search terms on the EDT and carry those immutable values through the worker; do not read editable CCCD/phone fields when a completion or dialog arrives. Keep the existing trim behavior. Do not add phone equivalence/normalization until its policy is approved. Use an exact CCCD criterion for any dedicated CCCD recovery; do not treat a generic substring hit as proof of identity.
- [ ] Define and preserve the current two-field OR/union intent, but bound the combined, de-duplicated result set to 50. Do not silently return partial candidates if either submitted criterion fails. Prefer one typed Application query and one success audit for a combined search; if separate handler calls remain, use distinct operation correlation IDs and fail the whole UI search if either fails. Never convert authorization/query/audit failure into “no matching patient.”
- [ ] Do not overwrite an unsaved draft merely because there is one hit. Keep selection explicit where a draft exists; cancel or no result leaves it unchanged. Only a deliberate selection may load a scoped patient, and the subsequent save remains an authorized update. This also prevents a late or stale search from replacing a newer draft.
