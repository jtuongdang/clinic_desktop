3. Two new focused synthetic tests were added to `ReceptionPanelActiveRoomBindingTest.java`, bringing the suite to 7/7 passing tests.

This review confirms resolution of the P1.3 active-room binding defect and its residuals, but does **not** claim REC-01, PAT-02, or SEC-01 gate closure.

## Follow-up resolution of residual edge cases (commit 13178f9, task a81c2ec3)

- **Duplicate room display names — resolved and verified.** Commit `13178f9` (task `a81c2ec3`) addresses ambiguous display names by introducing `clinicRoomChooserLabels(rooms)` in `PatientRegistrationFormPanel`. When two or more active rooms have the same name (case-insensitive), their labels are disambiguated as `TenPhong (#id)` while unique room names retain their original string unchanged ([`PatientRegistrationFormPanel.java:587–597`](../../clinic-desktop/src/main/java/vn/clinicmanagement/desktop/modules/reception/components/PatientRegistrationFormPanel.java#L587-L597)). In `toRegisterCommand`, the selected label is matched by index against `roomLabels`, falling back to exact room name matching, properly resolving the chosen `PhongKham.getId()` ([`PatientRegistrationFormPanel.java:704–717`](../../clinic-desktop/src/main/java/vn/clinicmanagement/desktop/modules/reception/components/PatientRegistrationFormPanel.java#L704-L717)). Verified by synthetic test `duplicateRoomNamesHaveDisambiguatedLabelsAndSubmitSelectedRoomId` ([`ReceptionPanelActiveRoomBindingTest.java:279–314`](../../clinic-desktop/src/test/java/vn/clinicmanagement/desktop/modules/reception/ReceptionPanelActiveRoomBindingTest.java#L279-L314)).
- **Failed room refresh — resolved and verified.** Commit `13178f9` (task `a81c2ec3`) updates `ReceptionPanel.refreshData()` so that when `roomsResult.isFailure()`, the panel invokes `ReceptionPanel.this.updateActiveRooms(List.of())` and displays the error message ([`ReceptionPanel.java:253–256`](../../clinic-desktop/src/main/java/vn/clinicmanagement/desktop/modules/reception/ReceptionPanel.java#L253-L256)). This ensures stale room selections and identities do not persist on UI when catalog loading fails. Verified by synthetic test `failedRoomCatalogRefreshClearsStaleRoomIdentityAndShowsCatalogMessage` ([`ReceptionPanelActiveRoomBindingTest.java:411–442`](../../clinic-desktop/src/test/java/vn/clinicmanagement/desktop/modules/reception/ReceptionPanelActiveRoomBindingTest.java#L411-L442)).
