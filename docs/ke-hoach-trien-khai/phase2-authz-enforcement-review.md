# SEC-AUTHZ-01B — Inventory application scope boundaries

**Review date:** 2026-11-05
**Mode:** Static, read-only source review. No database or external system was accessed; this document contains no patient records or copied sample values.

## 1. Approved boundary and review rules

The approved policy is one active role and one assigned `(facilityId, departmentId)` pair per session. A permitted operation must be scoped to that exact pair at the Application boundary; a facility-wide or system-wide legacy scope does not widen access. `DEC-AUTHZ-03` selected strict department isolation, including patient administration, insurance, history, and queue. `AUDIT_READ` is denied for every role, including `ADMIN`; self-granting or changing permissions for the active role is not authorized. These are policy constraints, not evidence that an authorization guard or permission seed is present ([approval](phase2-role-permission-matrix-approval.md#L7-L14), [security policy](phase2-security-policy-proposal.md#L10-L17), [implementation contract](phase2-implementation-contract.md#L7-L18)).

The policies for `DEC-AUTHZ-01/02/04a/04b/05/06/07/08` have since been approved and are recorded in the [Owner approval](phase2-role-permission-matrix-approval.md#L7-L28). Their runtime workflows remain denied until each has an implemented guard, audit behavior, persistence, and tests. This source review neither creates grants nor treats policy approval as implementation evidence. The proposal's table 5.2 describes matrix rows; the approval record controls the current policy ([matrix proposal](phase2-role-permission-matrix-proposal.md#L141-L180), [approval](phase2-role-permission-matrix-approval.md#L7-L28)).

## 4. Inferred cross-department leakage risks

The following are risks inferred from the unscoped paths above, not confirmed access from a running database:

1. A reception search can match a patient from another department or facility and return demographics plus the latest insurance card. A user can select that object and submit it for update; registration checks the room pair, but does not check the existing patient's authorized department or linked visit before updating the patient and insurance IDs ([search](../../clinic-application/src/main/java/vn/clinicmanagement/application/reception/SearchPatientsHandler.java#L20-L28), [mutation](../../clinic-application/src/main/java/vn/clinicmanagement/application/reception/RegisterPatientHandler.java#L70-L95)).
2. Queue results, room summaries, and active room choices can expose activity or metadata from other departments in the same facility and from other facilities because their list SQL has no session pair predicate ([queue](../../clinic-infrastructure/src/main/java/vn/clinicmanagement/infrastructure/persistence/reception/ReceptionQueueRepositoryImpl.java#L84-L127), [rooms](../../clinic-infrastructure/src/main/java/vn/clinicmanagement/infrastructure/persistence/facility/PhongKhamRepositoryImpl.java#L38-L42)).
3. Global CCCD uniqueness means a duplicate check can detect a match outside the current department. The current handler returns a generic duplicate message rather than the matched record, but UI then offers a global search path; this needs the approved non-disclosure behavior and strict scoped results, not a broader read grant ([duplicate check](../../clinic-application/src/main/java/vn/clinicmanagement/application/reception/RegisterPatientHandler.java#L70-L73), [UI response](../../clinic-desktop/src/main/java/vn/clinicmanagement/desktop/modules/reception/ReceptionPanel.java#L190-L209), [approved rule](phase2-role-permission-matrix-approval.md#L30-L34)).
4. Future child-resource lookups keyed only by visit, patient, invoice, or warehouse IDs could bypass the pair boundary unless they resolve and check the parent/resource pair at Application and SQL/repository boundaries. This is particularly material for entities that carry only facility or visit IDs, not both scope IDs.
5. Repository-level `NhanVienRepositoryImpl.getAll()` uses a shared select column list that includes `passwordHash`; no Application identity-management handler was found. If this broad repository method is later exposed, it should not be used as a desktop view model or trusted as a scope-filtered identity query ([column list and getAll](../../clinic-infrastructure/src/main/java/vn/clinicmanagement/infrastructure/persistence/identity/NhanVienRepositoryImpl.java#L30-L33), [getAll](../../clinic-infrastructure/src/main/java/vn/clinicmanagement/infrastructure/persistence/identity/NhanVienRepositoryImpl.java#L55-L58)).

## 5. Minimal dependency-ordered implementation split

1. **Complete SEC-AUTHZ-01A foundation before enabling guards.** Bring action codes and defaults/constraints into line with the approved contract, retaining fail-closed behavior and no permission seed until the approved policy rows can be represented safely. Current source still has five action values and a `CO_SO` model default ([enum](../../clinic-domain/src/main/java/vn/clinicmanagement/domain/common/enums/HanhDongQuyen.java#L3-L8), [model](../../clinic-domain/src/main/java/vn/clinicmanagement/domain/system/MaTranPhanQuyen.java#L6-L11)); contract scope and no-grant constraint are specified in [SEC-AUTHZ-01A](phase2-authz-foundation-contract.md#L1-L25).
2. **Add the Application authorization boundary.** Introduce an immutable authenticated actor created from the validated login result and pass it explicitly to every sensitive command/query. The evaluator should re-check active employee, assigned active role, exact currently assigned facility/department pair, and the approved matrix on each sensitive call; reject absent/stale context, missing or false rows, non-`KHOA_PHONG` legacy scope, and `AUDIT_READ`. Reuse existing identity assignment reads and matrix read port rather than trusting `UserSession` values ([scope reads](../../clinic-infrastructure/src/main/java/vn/clinicmanagement/infrastructure/persistence/identity/NhanVienRepositoryImpl.java#L182-L234), [matrix port](../../clinic-domain/src/main/java/vn/clinicmanagement/domain/repositories/ISystemRepository.java#L6-L9)).
3. **Guard and scope existing reception paths end-to-end.** Add actor/action enforcement to registration, patient search, queue reads, and room catalogs. Bind mutation target patient and insurance records to an authorized in-scope visit/department, not only to a valid room; filter queue, room and patient results at the repository query boundary. Preserve a generic non-disclosing response for a global CCCD collision as required by the approved policy.
4. **Gate the legacy/future panels before wiring data.** Treat dashboard visibility as UX only. For EMR, prescription, CLS, inventory, billing, appointments, audit, and identity administration, first add explicit Application use cases and repository adapters with resource-to-pair checks; only then connect the desktop surface. Keep unresolved DEC actions denied and do not implement an audit reader.

## 6. Synthetic allow/deny coverage

Use synthetic fixtures only. Minimum evaluator and handler/repository coverage:

- Allow only a role/action row permitted by the approved matrix when the actor's exact assigned pair and target pair match; allow must not be inferred for an unlisted/unknown action.
- Deny a different department in the same facility, a different facility, missing actor/context, inactive employee, unassigned/revoked role, and unassigned/revoked pair.
- Deny missing matrix row, `duocPhep=false`, each legacy scope (`CO_SO`, `CHI_NHANH`, `TOAN_HE_THONG`), and `AUDIT_READ` for every role including `ADMIN`.
- For patient/insurance, search and by-ID reads exclude another-pair targets; updates reject another-pair patient/card even when supplied IDs are valid. A cross-department synthetic CCCD collision returns only the approved generic response and never details from the other scope.
- For queue/rooms, same-date results include only the exact facility+department pair; other-department counts, patient names, rooms, visits, and statuses are absent.
- For visit-child resources, test exact-pair parent allow and cross-department/facility deny for EMR, prescription, CLS, billing, and appointment paths. For inventory, deny until the resource's department membership can be established; separately test any future mapping rather than assuming facility-only means department access.
- Verify audit denial and append behavior separately; no synthetic audit read should succeed in this policy phase.
