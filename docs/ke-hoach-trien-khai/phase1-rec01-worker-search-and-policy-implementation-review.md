## Residual notes and boundary

- The epoch is a UI freshness guard, not authorization. Handler authorization remains authoritative. The `TiepDonManHinh` fallback context path remains a residual; SEC-01 and PAT-02 stay default-deny and open.
- In-flight save form lock (`setComponentsEditable(formPanel, false)` in commit `1239784`), refresh failure error surfacing (`TiepDonManHinh.java:248-255`), distinct per-query correlation UUIDs, and search failure without partial results are verified by `TiepDonManHinhTacVuNenVaSearchGiaCoTest.java` (12/12 tests PASS in commit `644a904`). Combined-result capping at 50 is implemented in `TiepDonManHinh.java:622`.
- The policy still defines duplicate-code prompt/masking behavior. The registration handler maps an identity-conflict exception to generic `PATIENT_REGISTRATION_FAILED`; this review does not authorize identity recovery or infer safe cross-scope duplicate behavior.
- `createdBy` behavior was verified through source, synthetic handler tests, and JDBC parameter binding only. No clinicDb or SQL Server connection was made.
- **No REC-01, PAT-02, or SEC-01 closure is claimed. REC-01, PAT-02, and SEC-01 remain OPEN.**
