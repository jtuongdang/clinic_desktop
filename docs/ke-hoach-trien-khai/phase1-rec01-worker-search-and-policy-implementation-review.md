## Residual notes and boundary

- The epoch is a UI freshness guard, not authorization. Handler authorization remains authoritative. The `ReceptionPanel` fallback context path remains a residual; SEC-01 and PAT-02 stay default-deny and open.
- Search logic appears all-or-failure for returned handler failures, but the inspected tests do not exercise asynchronous stale search completion, two-query failure, combined-result capping, or correlation-ID uniqueness.
- The policy still defines duplicate-code prompt/masking behavior. The registration handler maps an identity-conflict exception to generic `PATIENT_REGISTRATION_FAILED`; this review does not authorize identity recovery or infer safe cross-scope duplicate behavior.
- `createdBy` behavior was verified through source, synthetic handler tests, and JDBC parameter binding only. No clinicDb or SQL Server connection was made.
- **No REC-01, PAT-02, or SEC-01 closure is claimed.**
