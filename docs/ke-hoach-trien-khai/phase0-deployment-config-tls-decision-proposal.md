## Owner decisions — PHASE0-DB-DEPLOY-DECISION-RECON-02 and PHASE0-DB-CONFIG-SOURCE-PRECEDENCE-OWNER-DECISION-01

**Decision date: 2026-11-06.** The following are approved policy requirements, not implementation authorization.

### Packaged database configuration

- **Approved source coverage:** the packaged desktop must support both process environment/secret injection and an external properties file selected through an explicit path/interface.
- **Approved per-key source precedence:** under `PHASE0-DB-CONFIG-SOURCE-PRECEDENCE-OWNER-DECISION-01`, if the same configuration key exists in both sources, environment/secret injection wins. The external file is a fallback supplying only keys absent from the environment.
- **Not approved:** implicit discovery beside the JAR or from the current working directory. No implicit path selection is authorized.
- **File path/interface resolved by the 2026-11-06 addendum:** `CLINIC_DB_CONFIG_FILE` selects an explicit absolute external properties-file path for IntelliJ and packaged-JAR launch; no implicit directory discovery.
- **Still unresolved for configuration:** blank/relative selector behavior; precedence between combined `DB_CONNECTION_STRING` and split values; blank or partial environment-value semantics and integrated authentication; how settings and secrets are split between sources and redacted; behavior and fallback for a missing, unreadable, or malformed selected file; properties syntax and duplicate/unknown keys; driver selection; URL construction/default database; and default values. The per-key rule does not decide these details, including whether blank values count as absent or how partial configurations are resolved. Do not infer these rules from existing resolver behavior or use a conventional path as a default.

### SQL Server TLS

- **Approved mandatory policy:** require encrypted transport and validate both the server certificate and server identity. Invalid, untrusted, expired, or hostname/identity-mismatched certificates must fail closed.
- **Explicitly not approved:** `trustServerCertificate=true`, disabled encryption, reliance on JDBC driver-default fallback, or any environment-specific validation/encryption bypass.
- **Implementation and test details, not Owner policy choices:** specify the JDBC options, trust-anchor provisioning, and managed certificate/hostname implementation, then test them to demonstrate they satisfy the approved policy. These details must not weaken or bypass the requirements above.
