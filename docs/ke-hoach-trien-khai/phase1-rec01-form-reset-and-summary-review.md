## Remaining edge cases

- Failed, denied, or exceptional refreshes do not replace the displayed queue/room summaries: the update path runs only for a successful queue result. The focused panel tests cover successful and empty snapshots, not refresh failure/staleness ([`ReceptionPanel.java:226–232`](../../clinic-desktop/src/main/java/vn/clinicmanagement/desktop/modules/reception/ReceptionPanel.java#L226-L232)).
- F1/F2 tests call the resolved Swing `Action` directly; they do not dispatch physical key events through a visible window or test precedence against other focused-window bindings ([`ReceptionActionBindingsTest.java:58–90`](../../clinic-desktop/src/test/java/vn/clinicmanagement/desktop/modules/reception/components/ReceptionActionBindingsTest.java#L58-L90)).
- `clearForm()` formats its registration timestamp from `LocalDateTime.now()` (JVM default zone); the reset test checks only that a timestamp-shaped value is present, not its clinic-zone interpretation ([`PatientRegistrationFormPanel.java:641`](../../clinic-desktop/src/main/java/vn/clinicmanagement/desktop/modules/reception/components/PatientRegistrationFormPanel.java#L641), [`ReceptionPanelFormResetAndSummaryTest.java:201–217`](../../clinic-desktop/src/test/java/vn/clinicmanagement/desktop/modules/reception/ReceptionPanelFormResetAndSummaryTest.java#L201-L217)).

This review assesses only the named behaviors and does **not** claim REC-01, PAT-02, or SEC-01 closure.
