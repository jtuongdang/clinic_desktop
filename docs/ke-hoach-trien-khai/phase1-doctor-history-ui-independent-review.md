## Actionable findings, ordered by priority

**P1 — Selecting an old queue row can conceal a session/scope replacement from the monitor.** The queue has no retained loading-context binding. In `onPatientChanged`, the old row is assigned and displayed, fresh contexts are captured, and `observedSession` is overwritten before any comparison with the context that supplied the queue ([DoctorStationPanel:192–212](../../clinic-desktop/src/main/java/vn/clinicmanagement/desktop/modules/doctor/DoctorStationPanel.java#L192-L212)). The monitor then returns when that overwritten context equals the current context ([253–262](../../clinic-desktop/src/main/java/vn/clinicmanagement/desktop/modules/doctor/DoctorStationPanel.java#L253-L262)).

Source-derived trigger: load queue under session A, replace the active session with B (different UUID and/or exact pair), then select an A row before the 500 ms timer runs. B's matching actor passes; the A queue and patient/visit summary remain displayed, and history is requested under B. Completion checks compare against B, so they do not detect the queue's A provenance ([66](../../clinic-desktop/src/main/java/vn/clinicmanagement/desktop/modules/doctor/DoctorStationPanel.java#L66), [225–240](../../clinic-desktop/src/main/java/vn/clinicmanagement/desktop/modules/doctor/DoctorStationPanel.java#L225-L240)); lifecycle replacement is available through [SessionLifecycleService:115–128](../../clinic-desktop/src/main/java/vn/clinicmanagement/desktop/core/session/SessionLifecycleService.java#L115-L128). Application history guards still constrain B's query; this finding concerns retained A data and mixed UI context, not a demonstrated SQL authorization bypass. It violates the required clearing/binding behavior ([UI contract:43](phase1-doctor-history-ui-contract.md#L43)).

Follow-up: bind the rendered queue to its authorization context; before accepting selection, compare the complete current context, clear/invalidate on mismatch and reload. Do not let selection acknowledge a new session while retaining old rows. Add a synthetic A→B-before-monitor regression, including same-pair/new-session-ID replacement. Existing [DoctorStationPanelTest:156–181](../../clinic-desktop/src/test/java/vn/clinicmanagement/desktop/modules/doctor/DoctorStationPanelTest.java#L156-L181) covers logout followed by an explicit monitor call, not this ordering. **Evidence level:** source-derived race; not reproduced through a live dashboard flow.

**P2 — A pending history request is presented as verified empty.** Selection calls `clearHistory()`, which sets “Chưa có dữ liệu tiền sử bệnh đã xác thực.”, then launches the worker without calling the available `showLoading()` ([DoctorStationPanel:197–213](../../clinic-desktop/src/main/java/vn/clinicmanagement/desktop/modules/doctor/DoctorStationPanel.java#L197-L213); [DoctorHistoryPanel:14,49–58,77–79](../../clinic-desktop/src/main/java/vn/clinicmanagement/desktop/modules/doctor/components/DoctorHistoryPanel.java#L49-L79)). Until the read completes, a slow allergy/history query therefore looks like a successful empty result. Use the existing loading state after clearing and context validation; reserve the empty message for successful empty responses. Add a latch-controlled pending-state assertion. Current tests check completed content/empty states and delayed stale responses, but not loading text ([DoctorHistoryPanelTest:17–41](../../clinic-desktop/src/test/java/vn/clinicmanagement/desktop/modules/doctor/components/DoctorHistoryPanelTest.java#L17-L41); [DoctorStationPanelTest:125–153](../../clinic-desktop/src/test/java/vn/clinicmanagement/desktop/modules/doctor/DoctorStationPanelTest.java#L125-L153)). **Evidence level:** verified call path, not a visual observation; consistent with existing feedback guidance ([UI standard:520–524](../../UI_CODING_STANDARDS.md#L520-L524)).
